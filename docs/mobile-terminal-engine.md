# The phone's terminal engine: xterm.js in a WebView (2026-10-04)

Until 0.9.114 the phone drew terminal panes with libghostty (`expo-libghostty`, a native view). At the user's request it now uses upstream Orca's own mobile terminal, xterm.js inside a WebView (`mobile/src/terminal/TerminalWebView.tsx` and `document/`), and Ghostty is removed: the dependency, its patch, the view and its helpers. `terminal-xterm-only.test.ts` fails if any of it comes back.

Ghostty was chosen in 0.4 for speed: on Claude Code's repaint stream xterm.js behind the 48 ms write coalescer painted about 13 frames/s against Ghostty's 55. That cost is accepted with this change; see "Performance" below and check it on a phone.

This is the porting agent's record, followed by the fixes made after two Opus reviews.

## Performance (report only)

The old reason for Ghostty: xterm behind the write coalescer painted about 13 frames/s against Ghostty's 55 on Claude Code's repaint stream. The window that matters now:

- `mobile/src/terminal/terminal-write-coalescer.ts:9`, `TERMINAL_WRITE_FLUSH_WINDOW_MS = 48`. The first write after an idle gap is delivered synchronously (leading edge, no echo delay), then at most one flush per 48 ms, about 20/s, with a 512K-unit pending cap (`:14`). It is used by `use-terminal-webview-controller.ts` (`createTerminalWriteCoalescer`), which both native and web mounts share.
- Document side: `document/write-queue.ts` holds writes up to `SCROLL_WRITE_HOLD_MAX_MS = 1200` while a scroll gesture is live (`:7`).
- Not changed. Watch on the phone: a Claude Code turn that repaints continuously, scrolling inside it, and whether the pane feels like 13 or 20 frames/s.
